Задача: `docs/tasks/MEMORY_HUNT.md`. Исходно помещалось 17 сдвигов из 32 (не хватало 534 байт). Итог: **32/32**,
скорость не хуже (2,8: 45,4 шага/с; 5,6: 26,9; 5,10: 34,1 → 39,8 — полный кэш сдвигов). Счётчик: `node tools/bench/ps-alloc.js build/<каталог>`.

## Отвергнуто

| Кандидат | Почему |
|---|---|
| Окно E500..E700 «пустой title spill» (вторая модель, 512 байт) | Это середина кэша тайлов (образы 54–74). Проверка «0 обращений» шла в комнатах с ≤ 53 образами; в 1,9 (81 образ) все 14 попавших туда сдвигов затираются, экран расходится с эталоном (70 клеток). Воспроизведение: `tilecheck` в scratchpad; не брать |
| MSX-часть таблицы `blk_9FD2` (+0F..+3F, 49 байт) | По сканеру всех комнат читаются все байты +00..+4F |
| `full_raw`: полосы тайлов 9A/9B, C8–CD (56 байт) | 9A/9B не читаются (мечи через стабильные образы), но их маски понадобились бы `object_colors.py` как новые (лимит 24 исчерпан); C8–CD читаются в тёмных комнатах |
| `force_tiles`, `trc_rebuild` (не выполняются) | Часть живого пути смены цвета (`room_color_changes` 708 вызовов, `tile_recolor` 7576 за сканер): достижимы при редких сменах цвета групп |
| `title_packed` (1282), копия темы заставки (694) | Нужны для GAME OVER |
| Свёртка `fl_fast3`, `enemy_mix` (вторая модель) | −16…−20 % и −4 % скорости |
| Квазидиск | «отставить» (владелец) |

## Инструменты
`tools/bench/ps-alloc.js` (сдвиги), `tile-cache-use.js`, `nes-dlist-overflow.js`, `nes-hit-boxes.js`;
`COVER=`/`ACCESS=` в `tools/vec_emu.js` — карты выполнения/обращений (сканер всех комнат — отдельными процессами на уровень).
Ловушки: «не тронуто стендами» ≠ «свободно» (кэш тайлов E000..E798, буферы спрайтов F9..FF 00..2F/D0..FF, dlist при длинных
списках); абсолютные адреса внутри `ps_boot_source` недопустимы.
