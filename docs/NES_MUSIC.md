# Музыка и SFX NES

Разобран локальный `orig/nes/monty.nes`, 40 976 байт, SHA-256
`453a6a9198b11cf6f948f5b61ab98dd7e6fbf7928a7b257941d4f5e7aa4a54fb`.
Извлечены три музыкальные программы и девять разных звуковых эффектов.
Названия ниже описательные, по местам вызова; автор музыки не установлен.
`src/native` не изменялся.

## Дорожки

Номер соответствует подсонгу NSF (нумерация с 1).
Время музыкального цикла рассчитано при измеренном NTSC-кадре
0,016639267340 с (≈60,099 Гц).

| NSF | Файл | Смысл / вызов | Цикл или экспорт |
|---:|---|---|---:|
| 1 | `title.wav` | Титульная тема, `$B8E0 → $8620` | 2560 кадров, 42,597 с |
| 2 | `pyramid.wav` | Вход в пирамиду на канате, `$9880 → $863A` | 1024 кадра, 17,039 с |
| 3 | `treasure.wav` | Особый переход к сокровищнице, `$9CD6 → $9CF3 → $8654` | 640 кадров, 10,649 с |
| 4 | `sfx_door.wav` | Открытие двери, `$A2C9 → $8600(1)` | 0,699 с |
| 5 | `sfx_jump.wav` | Прыжок, `$A834 / $AB32 → $8600(2)` | 0,433 с |
| 6 | `sfx_sword.wav` | Враг побеждён мечом, `$A541 → $8600(3)` | 0,433 с |
| 7 | `sfx_pickup.wav` | Подбор предмета, `$A34F / $A3D6 → $8600(4)` | 1,048 с |
| 8 | `sfx_life.wav` | Дополнительная жизнь, `$809E → $8600(5)` | 1,448 с |
| 9 | `sfx_landing.wav` | Окончание скольжения, `$9FF5 / $9FFC → $8600(6)` | 0,399 с |
| 10 | `sfx_land.wav` | Приземление, `$9FC5 → $85F7(1)` | 0,499 с |
| 11 | `sfx_death.wav` | Гибель, огонь, лазер — один шумовой эффект; `$A429 / $A453 / $A52E → $85F7(2)` | 0,566 с |
| 12 | `sfx_pole.wav` | Скольжение по шесту, `$A630 / $A639 → $860E` | пример 1,331 с |

SFX 4–9 используют второй pulse; 10–11 — noise. Их темп берётся из общего
счётчика звукового драйвера, поэтому экспорт фиксирует обычные 8 кадров на шаг.
Длительности включают короткий тихий хвост. Эффект окончания скольжения
изначально очень тихий, отдельная нормализация громкости не применяется.

Шест не имеет конечного потока нот. `$A630` при состоянии `$0790 & $80`
увеличивает Y героя на 2 и вызывает `$860E`. Процедура ставит `$07EF=$10`;
`$87FC` задаёт `$4007=1`, затем каждый кадр пишет `$4006=Y`, `$4004=$BF`,
`$4005=$08`. Экспорт воспроизводит Y=64…190 за 64 кадра и затем остановку.
Для другой траектории следует заново вызвать оригинальный драйвер с другим Y;
выгруженный файл является одним примером этого параметрического звука.

Поиск вызовов `$8600`, `$85F7`, `$860E` и записей в APU не выявил других
отдельных семейств эффектов: шесть pulse-потоков, два noise-потока и шест.
Остальные записи вне драйвера относятся к аппаратному сбросу, DMA и контроллеру.

## Где лежат музыка и драйвер

Необычная деталь: ноты находятся в **CHR-ROM `$0800–$0FFF`**, в области,
доступной через PPU. Это данные, хотя в просмотрщике тайлов выглядят как графика.
Драйвер занимает PRG `$81F5–$8821`, его таблицы — `$D334–$D45E`.

| Вход | Назначение |
|---|---|
| `$8588` | Включить четыре APU-канала через `$4015=$0F`, сбросить звук |
| `$85EE` | Остановить фон, приглушить каналы (`$07EE=1`) |
| `$8620` | Тема 1: таблица `$D3DB`, 4 ссылки на паттерны, 10 кадров/ноту, 4 канала |
| `$863A` | Тема 2: таблица `$D3FB`, 2 паттерна, 8 кадров/ноту, 4 канала |
| `$8654` | Тема 3: таблица `$D40F`, 2 паттерна, 5 кадров/ноту, 3 канала |
| `$866E`, `$868B` | Общая инициализация и загрузка указателей потоков |
| `$872D` | Чтение очередных нот из CHR через `$2006/$2007`, обычно из NMI `$8FF7` |
| `$86C6` | Звуковой шаг основного цикла, программные огибающие и продвижение |
| `$85F7(A)` | Запуск noise: ID 1 → `$D459`, ID 2 → `$D45C` |
| `$8600(A)` | Запуск pulse-эффекта ID 1…6; приоритет `A >= $07EF` |
| `$860E` | Включить процедурный тон шеста |

Цикл темы — число паттернов × 64 ноты × кадров на ноту. Последняя ссылка
титульной темы повторяется; в экспорт сохранён порядок программы, без сокращений.

В потоке pulse/triangle обычная нота занимает два байта: младший байт таймера
и упакованные старшие 3 бита таймера + 5 бит номера программной огибающей.
`$FE` удерживает предыдущую ноту, `$FF` даёт паузу; эти команды однобайтовые.
Noise кодирует период и огибающую в полубайтах. Таблица переходов огибающих
начинается в `$D3B9`, функции — с `$81F5`.

При `$07D4=0` читатель загружает ноты и ставит флаг готовности. `$86C6`
считает `$07CF` до `$07EA`; на границе ноты вызывает `$87C2` (pulse SFX),
`$879C` (noise SFX), `$859B` (запись нот), затем `$85D7` продвигает указатели.
`$07D0` считает 64 позиции; `$870A` переключает паттерн. На каждом кадре
`$85AD` обновляет огибающие, `$87FC` — тон шеста. При `$07FD>=0` шаг выключен.

В титульной теме есть специальные позиции `$3D/$3E` третьего паттерна,
где огибающая зависит от контроллера `$00`. Экспорт фиксирует нейтральный ввод 0.
Полученные циклы — воспроизведение при этом вводе, без интерактивного изменения.

## Форматы и воспроизведение

Генератор `tools/nes/music/extract_music.py` исполняет оригинальные процедуры
на существующем локальном 6502-исполнителе. В JSON каждая запись —
`[номер_кадра, адрес_APU, значение]`, и отдельно записана начальная настройка.
Первый цикл содержит начальное состояние; второй и третий циклы совпадают
по событиям. Плеер сохраняет первый и второй, затем повторяет второй без
сброса состояния APU. Программные огибающие уже рассчитаны оригинальным кодом.

Для изоляции SFX вызываются `$8588`, `$863A`, `$85EE`, затем `$07D4=1`:
фон молчит, темп 8 сохраняется, читатель не подставляет застывший аккорд.
После этого вызывается исходная процедура эффекта.

NSF v1 содержит 12 подсонгов, LOAD/INIT `$8000`, PLAY `$8080`, NTSC 16639 мкс.
Из ROM копируются только драйвер, его таблицы и музыкальные CHR-данные.
CHR переносится в CPU `$E000–$E7FF`, указатели сдвигаются на `$D800`.
Читатель `$872D–$879B` заменён эквивалентным чтением через CPU-указатели,
поскольку NSF не предоставляет PPU/CHR. Секвенсор, огибающие, SFX-парсеры
и запись в звуковые регистры остаются оригинальными. INIT очищает звук,
сохраняет стек вызывающего плеера и отключает frame IRQ через `$4017=$40`.
Параметризованный пример шеста реализован короткой обёрткой PLAY.

`apu.js` — самостоятельный JS-модуль без зависимостей, один код для браузерного
AudioWorklet и WAV-рендера в Node.js. Есть два pulse, triangle с linear counter,
noise с 15-битным LFSR, length/envelope/frame counters, нелинейный NES-микшер,
фильтры 90/440 Гц и 14 кГц, четырёхкратная передискретизация.
Аппаратный sweep и DMC не нужны этим данным; попытка их включить вызывает ошибку.

**Ограничение JS:** порядок записей внутри кадра сохранён, но точные CPU-такты
записей не записаны. Это специализированный синтезатор с точностью событий
до кадра, а не полный NES-эмулятор; формы волн не обязаны совпадать sample
в sample с MAME. NSF позволяет исполнять сам драйвер в отдельном NSF-плеере.

`player.html` содержит всё внутри одного файла. Раздельный `index.html`
читает соседние JS-файлы. Доступны три темы, сворачиваемый список SFX,
пауза/повтор, громкость, отключение четырёх каналов, сохранение WAV и NSF.
Экспорт WAV: mono PCM16, 44 100 Гц; музыка — два цикла с затуханием 1,5 с,
эффекты — один проход с затуханием последнего тихого хвоста 0,03 с.

## Проверки

- Экспортированный NSF сравнен с оригинальными ROM-процедурами по всем записям
  APU: по три цикла каждой темы и 512 кадров каждого SFX, включая инициализацию.
  Единственное дополнительное действие NSF — отключение IRQ `$4017=$40`.
- Независимый MAME: **23 529 совпавших записей** за 8832 звуковых шага:
  один полный цикл каждой темы и по 512 кадров девяти SFX.
  Используется изолирующая обёртка только в памяти эмулятора: NMI отключён,
  файл картриджа неизменен. Это проверка исходного звукового кода в MAME,
  не запись полноценного игрового прохождения. События из `capture_music.lua`
  сверяются по кадрам и порядку; ошибка/незавершённый захват дают ненулевой exit.
- Game Music Emu (`libgme` 0.6.5) загрузил NSF и проиграл все 12 дорожек без
  предупреждений; каждая тема проверена в течение полного цикла + 0,3 с,
  SFX — по 2 с. Все дорожки дают ненулевой сигнал.
- JS WAV: все 12 файлов без клиппинга, peak 0,037…0,617. Тихий девятый
  подсонг подтверждён также GME. Проверены частота тестового pulse при
  44,1/48 кГц, тишина при выключении каналов и сохранение APU при повторах.
- В браузере проверены запуск AudioWorklet, пауза, автоматическое завершение
  SFX и реальное скачивание `sfx_jump.wav`; ошибок в консоли не было.

Команды и использование JS: `tools/nes/music/README.md`.
Игровые данные, NSF, WAV и JSON находятся только в игнорируемом `build/nes/music`;
в git входят инструменты, исходники плеера и этот отчёт.
