## Этап 1: независимые прямоугольники и сохранённый фон

Кэш по Y хранит только потенциально пересекающиеся пары. На каждом выводе
они проверяются по объединению старого/нового X; непересекающиеся враги
не включают общий crit_plan. Порядок слоёв Джо сохранён. Для независимого
врага с прежней обрезкой и без изменённых клеток добавлено действие 4:
сохранённый фон объединяется с новой маской без восстановления/сохранения.

В 5,7 подготовка disp_prep: 49 506 → 42 432 такта/вызов; crit:
45 402 → 42 241. spr_plan: 17 183 → 13 608; crit_plan:
11 133 → 5 808. Средняя скорость и ровность тяжёлых комнат не достигнуты.
Повторное использование фона применимо редко: 230 действий 4 против
965 обычных восстановлений на длинном окне 5,7; обрезка/столбцы часто меняются.

Память: 28 байт band_pairs в свободном 66E0–66FB после spr_new.
Одноразовый ps_build (368 байт) копируется в E000 до построения тайлов;
его исходный участок после копирования отдаётся сдвигам. Число сдвигов
сохранено: **68**; ps_heap=6517. В критической части SP не используется для записи,
новых DI нет.

Проверки этапа 1: обе сборки; slsall — четыре допустимые строки 7048=0/1
и совпадение VRAM; scrchk 2000: 1521/957/1446 экранов, 0 ошибок;
FANY=1 cellchk 3000 tp: 410 проверок, 0 ошибок; native-video 3000:
68 точных неизменных сдвигов, скачок ≤3, отставание ≤5, фазы 698/700.
nsteps: 2184 кадра, 43,5 шага/с; rsplit: 17 смен, обычные
2311 шагов / 2341 кадр, 49,4 шага/с.

## Этап 2: компилированные живые клетки

При каждой порции анимации корзина не менее 8 клеток получает программу
MVI M,N / DCR L только для строк, различающихся хотя бы в двух кадрах.
Состояние отдельной клетки не угадывается: при FIRE_K=3 она могла пропустить
несколько фаз. Общие строки не записываются, остальные берутся из нового
готового образа. Для 38 меняются 6–7 из 8 строк, для D0/D1 — 5, для
D2–D5 — 7, для E8 — **одна** (строка 2). Лента проходит целиком одним вызовом.
FIRE_K=3 и частота запросов фаз не менялись. Цвета используют полный путь,
при следующей анимации код строится заново, поэтому устаревших цветов нет.

Буфер 112 байт в начале бывшего одноразового построителя; максимальная
программа 91 байт. В E000 дополнительно перенесены mask_keys_init,
trim_build, lv_init, game_init, unpack и исходное сжатое ОЗУ; их исходное
размещение отдано сдвигам после копирования. Теперь сдвигов **70**, ps_heap=65BF.
Временный E000 занят только при загрузке до первого построения тайлов.

Контрольное окно 7,2: force_live_t 38 643 → 32 086 тактов/вызов
(включая компилятор). Четырёхфазная таблица полных переходов для каждого
огня не требуется: учитывается объединение меняющихся строк всех фаз.
Экономия на 38 ограничена: 7 строк из 8 действительно различаются.

Все обязательные проверки этапа 2 пройдены: обе сборки; slsall — четыре
допустимые строки; scrchk 2000 — 1452/934/1427 экранов, 0 ошибок;
cellchk 3000 tp — 419 проверок, 0 ошибок; native-video 3000 — 70 сдвигов,
скачок ≤3, отставание ≤5, фазы 699/700. nsteps: 2183 кадра, 43,5 шага/с;
rsplit: 2311 обычных шагов / 2342 кадра, 49,3 шага/с.

Дополнительная проверка native-video с ROOM=5,7/7,3 и четвёртым черепом
выявила ранее не покрытое ограничение: редкие скачки до 10–12 точек при
отставании больше 8, которое rolling_pose не ограничивал. Исправление и
повторная проверка входят в этап 3. Эталон и пороги не ослабляются.
