# Разбор MSX-версии Montezuma's Revenge

Основа порта — MSX-картридж Muffie (`orig/msx/monty_msx.rom`, id 1562). Решение владельца от 26.10.2026:
MSX-версия совпадает с ColecoVision, поэтому разбираем только её.

## Устройство картриджа (установлено 26.10.2026)
MSX-версия — это **игра ColecoVision, запущенная на MSX вместе с BIOS OS7**:

| ПЗУ MSX | Во время игры | Что это |
|---|---|---|
| 400A–65B8 | ОЗУ 0000–25AE (копирует 669D) | 0000–1FFF — BIOS OS7 ColecoVision на портах MSX; 1F61–1FFF — таблица переходов OS7 (53 входа); 2000–25AE — прослойка Muffie |
| 65B9–6B7F | не нужно | INIT MSX: поиск слотов ОЗУ, заставка «Muffie» через BIOS MSX, мелодия через WRTPSG, копирование и `jp 2000h` (66A8) |
| 6B80–7FFF | — | заполнитель 4C |
| 8000–BFFF | 8000–BFFF как есть | **картридж ColecoVision, 16 КБ**: заголовок (сигнатура заменена на 4C4C), указатели 7300/72E0/7210/7005, старт 8025 |

Во время игры A8 = DF (записывается один раз в 200C): ОЗУ в 0000–7FFF и C000–FFFF, картридж в 8000–BFFF.
Переключений слотов больше нет. ОЗУ Coleco — 7000–73FF; стек OS7 — 73B9.

Прослойка 2000–25AE:
- 2000 — A8 := DF, переход в 8025;
- 2011 — DECODER OS7 (вход 1F79 перенаправлен сюда): опрос матрицы клавиатуры MSX вместо пультов Coleco;
- 20C6 — обработчик прерывания кадра (IM1 0038 и NMI 0066 ведут сюда; у Coleco это NMI от VDP);
- PSG: порты A0/A1 в прослойке и в картридже (OUT A0 — 4 места). У Coleco звук SN76489, его следы ещё не сверены.

Порты Coleco в BIOS (80, C0, FC, FF) остались в отдельных местах — это неиспользуемые ветки, проверить по покрытию.

## Вызовы OS7 из игры
Имена входов — по общедоступному списку точек входа OS7 (1F61 PLAY_SONGS не проверено). Частота вызовов:
WRITE_REGISTER 18, PUT_VRAM 15, FILL_VRAM 9, TURN_OFF_SOUND 6, INIT_TABLE 5, REFLECT_VERTICAL 3, LOAD_ASCII 3,
WR_SPR_NM_TBL 2, READ_REGISTER 2, GET_VRAM 2, REFLECT_HORIZONTAL 1, INIT_SPR_ORDER 1 и др.
Для Вектора эти услуги OS7 и прослойку нужно написать заново; картридж 8000–BFFF — это сама игра.

## Старт, комнаты, телепорт (модель: `startGame`, `teleport`, `cheats` в tools/msx1.js)
- Старт: клавиша уровня «1»..«3», затем огонь (пробел). До огня — вступление в комнате (0,8) = 0 с флагом 705F бит 2;
  огонь — переход на два столбца вправо (8F13) в стартовую (0,10) = 2; 8AB3 при столбце 10 снимает флаг и
  вызывает 8E7E (инвентарь, точка возрождения).
- Пирамида: 9 рядов по 3, 5, …, 19 комнат = 99. Ряд — 71A7, столбец — 71A8 (в ряду r столбцы 8−r..10+r).
  Номер = A4C5[ряд] + столбец (A4B5); A4CE берёт из таблицы 9477 начало и конец описания комнаты (7190/7192);
  A067 разбирает поток описания (байт кода 7196, 3 параметра 7197..) и рисует комнату.
- Смена комнаты: 8DFA (влево/вправо, 71A8 ±1), 8F04/8F13 (ряд); при смене ряда A9B3 -> 8EB0: палитра этажа
  (7 байт из 93C0 + 7·min(ряд,8) в таблицу цветов) и темнота (ряд ≥ 9 − 71A6 без факела — предмет 53).
- Герой: спрайт 0 в 7300 (Y)/7301 (X); состояние 7079 (0/4 стоит, 6 падает, 9 гибель); жизни 7049 (старт 6).
  Падение: высота 7300 − 707C (Y в начале падения), гибель при ≥ 1Ch (8AD5).
  Точка возрождения: 8E7E копирует состояние в 707C–7085.
- Телепорт: ряд и столбец + 7079 := 9 (гибель); при возрождении A067 рисует новую комнату; затем вызов 8EB0.
  Читы: 8AD6 := FF (любое падение безопасно), 7049 держится на 6.

## Описания комнат (установлено 26.10.2026, `tools/roomdec.py`)
- Таблица `ROOM_TAB` 9477 (100 слов) — начала потоков 99 комнат, конец потока = начало следующей;
  потоки `ROOM_DATA` 9541–9FBF (2687 байт). 26 комнат служат подописаниями других (вызов 3E/3F, 3F — с
  зеркалированием всей игровой области по возврату, `MIRROR_ROOM` AB29, пары тайлов `MIRROR_PAIRS` AB0C).
- Запись: код K и 0–3 параметра; позиция = ((K>>6)&3)<<8 | p1 (номер клетки), набор тайлов = `ROOM_TS`[K&3F] →
  `TILESETS` 9FD1. Шесть примитивов (таблица A20A): прямоугольник, треугольник с лесенкой, столбец, полоса с
  концами, столбец с шапкой, узор. 10/11 — конец потока на младших уровнях (71A6 = номер уровня 1..3).
  20–28 предметы 2×2, 29–2F двери, 30–32 враги (спрайты, A405); объекты — только на верхнем уровне потока,
  у каждого бит «взят/открыт» в 70C0 + 2·комната (`OBJ_TAKEN` A514).
- Перед потоком `CLEAR_ROOM` A1DF: строки 5–23 := 0, строки 0–4 := 8 и рамка (AA5D); после — инвентарь A548.
- Сверка: декодер на Python повторяет таблицу имён строк 5–23 на выходе из `DRAW_ROOM` A067 во всех
  297 комнатах (99 × 3 уровня) побайтно (`tools/room_nt.js` снимает эталон, `tools/roomdec.py check`).
  Строки 0–4 (рамка, инвентарь, жизни, номер уровня) — отдельный код интерфейса, ещё не повторён.

## Ресурсы (`tools/export_res.py` → build/res/)
- Тайлы: 4 банка шаблонов — фазы анимации, игра циклически ставит R4 = 0, 1, 2, 5 (VRAM 0000/0800/1000/2800),
  банки отличаются на 13–17 тайлов (огонь, верёвки…); тайлы E0, E8 переписываются (1D15 из AE34).
  Других записей в шаблоны тайлов и спрайтов во время игры нет. Источники в ПЗУ разбросаны (шрифт — OS7 14A3),
  поэтому ресурсы берутся из VRAM после старта.
- Цвета: база (32 байта) + палитра этажа 93C0 + 7·min(ряд, 8) → элементы 1..7 (`FLOOR_PALETTE` 8EB0).
  Темнота: ряд ≥ 9 − уровень → элементы 0–2, 10–13, 15–18 := 0 (297 из 297). Элемент 1C (E0–E7) игра
  обнуляет в комнатах 30, 37, 42, 44, 52, 83 — мигание.
- Сверка: таблица имён модели, отрисованная только из выгруженных ресурсов (с её цветами и R4), совпадает
  с экраном модели без спрайтов по пикселям во всех 297 комнатах. Карты уровней — build/res/map_L<у>.png.

## Видео
TMS9918A Graphics I (R0=00, R1=E2): имена 1800, шаблоны 0000, цвета 2000, атрибуты спрайтов 1B00, шаблоны спрайтов 3800;
спрайты 16×16, прерывание кадра включено.

## Инструменты
- `tools/openmsx/dump-entry.tcl` (машина `MontyMSX`, копия в `tools/openmsx/MontyMSX.xml`, BIOS `monty_bios.rom` в
  `~/.openMSX/share/systemroms`) — снимки entry (вход в 2000h), title, game16, game20 и журнал записей в A8.
- `tools/build_image.py` — `build/monty_entry.bin`: ОЗУ на входе + картридж 8000–BFFF.
- `tools/msx1.js` — модель MSX1 в раскладке игры (60 Гц, IM1 по кадру). `tools/cmpsnap.js`: от entry с вводом
  старого сценария до game16/game20 — PC совпадает (A5CA), в ОЗУ 23–58 байт и в VRAM 34–38 байт расходятся
  сдвигом фазы (момент входа 4,789 с определён с точностью до кадра, задержек VDP модель не знает).
- `tools/cover_run.js <уровень>` — покрытие обходом: каждая из 99 комнат телепортом + 1500 кадров случайного ввода
  с читами; уровни 1–3 вместе — 3956 адресов команд (около 2 мин на 3 процесса).
- `tools/rooms.js <уровень>` + `tools/pyramid.py <уровень>` — все комнаты уровня, лист `build/rooms/pyramid<у>.png`.
- `tools/cov_entries.py` + `tools/ghidra/run.sh` — входы из покрытия, повторять до нулевого остатка.
  Остаток — 816D, 8179 и 9207: перекрывающиеся команды (поток через байт E5 внутри `ld de,01E5h` в 816A;
  `call 91D9h` в 9207 при входе в 9208).
- `tools/mkctl.py` -> `build/auto.ctl` (заготовка), рабочий — `src/monty.ctl`; `tools/build_skool.sh` — skool, asm,
  html и проверка побайтной пересборки.

Код: 0000–22C5 (BIOS и прослойка), 8025–B104 (игра). Данные игры — 9377–A067 и B105–BFFF, их ещё предстоит разметить.
