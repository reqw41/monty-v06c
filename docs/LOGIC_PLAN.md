# Нативная логика на i8080 через JS-модель (с 26.10.2026)

Решение владельца: логику Coleco/MSX переписать заново — сначала **JS-модель** (сверка с MSX по итерациям),
потом **i8080 вручную с оптимизацией** (сверка с моделью/эталоном). Программный VDP заменяется прямыми
вызовами: логика сама рисует в экран Вектора (тайлы — кэш изображений + POP, спрайты — ячейки фона в
невидимой плоскости + POP), без виртуальной VRAM и сравнения «было/стало». Образец — jetpac-v06c
(docs/LOGIC_PLAN.md там).

Нынешняя сборка (транслятор tools/z2i.py + слой OS7) остаётся рабочим запасным вариантом и эталоном
поведения на Векторе.

## Этапы
0. **Эталон** — модель MSX tools/msx1.js в режиме coop (кадр — в ожиданиях A5CA/8C19), шаг = итерация
   главного цикла A5D1 -> A5D1. Трассы по сценариям: ОЗУ игры 7000-733F, таблица имён, цвета, атрибуты
   спрайтов, банки шаблонов, звук (байты SN76489 по кадрам). Сценарии: случайная игра на уровнях 1-3
   (с жизнями), обход 99 комнат телепортом, смерти разных видов, двери/ключи, лазеры, факел (темнота),
   сокровищница, конец уровня. Инструмент — по образцу tools/lockstep.js.
1. **JS-модель** (src/model/): главный цикл, процессы таблицы A8A1 (91E5, 8F5F, 88D1, A8D6), обработчик
   кадра A9B3 (враги A7A1, анимации A92F, звук AC6D, ввод 8C1F), комнаты (декодер — tools/roomdec.py уже
   есть), герой (состояния 8913: ходьба, прыжок, падение, лестница, верёвка, цепь, гибель), предметы,
   двери, счёт, инвентарь. Состояние — те же ячейки 7000-73FF (чтобы сверять 1:1); вывод — события
   «клетка (x,y) := тайл», «спрайт k := (x,y,имя,цвет)», «цвета группы», «банк R4».
2. **i8080** (src/vec/native/): та же раскладка ОЗУ игры, логика по модели с оптимизацией (регистры вместо
   ячеек, таблицы вместо цепочек сравнений), вывод напрямую.
3. **Сверка**: модель против эталона MSX; i8080 против модели (ОЗУ игры + события вывода).

## Уже сделано для вывода (в нынешней сборке)
- Банки шаблонов: банк 0 — E000, различия банков 1, 2, 5 — только 17 тайлов (04-06, 38, A0, A3, A4, A7,
  B8-BA, D0-D5), dslot/dstore; сверка шаблонов (PATS=1 в tools/lockstep.js) — совпадение.
- Невидимая плоскость: E000 банк 0, E800 dslot, E900 различия, F300 кэш тайлов (tslot), F400 изображения,
  F900-FEFF ячейки фона спрайтов (6 x 256), FF00-FFFF свободно.
- Кэш изображений тайлов и вывод клетки через POP (src/vec/cell.asm).

## JS-модель — готова (26.10.2026)
Вся покадровая логика игры — в src/model/ (подмены Z80-процедур в модели MSX, `src/model/hooks.js`):
| модуль | что |
|---|---|
| core.js | регистры, память, подмена с возвратом (hook) и с переходом (jump), z() — вызов Z80 из модели |
| main.js | главный цикл A5D1: процессы A8A1, ожидания кадра A5D8/A5CA/8C13 (кадр = A9B3) |
| frame.js | обработчик кадра A9B3, банки шаблонов A92F/A97A, лазеры A8D6, A894 |
| hero.js | герой 88D1: машина состояний 8913 (метки оригинала), шаг/стены/лазеры 8D80, смена комнаты 8DE8/8E0C, гибель 8DA2, точка возрождения 8E7E, конец игры (до ожидания огня — исключение GameOver) |
| enemy.js | враги A7A1 (стековые ветви дословно), A69F, ABED |
| collide.js | процесс 91E5 (факел, амулет, меч, столкновения), процесс 8F5F (двери, огонь, предметы), инвентарь 908F/909C/A56C/901B, флаги взятия 90A5/90C8/92A2, кадр героя 92DC/9305, счёт AF70/A587, 919A |
| drawroom.js | рисование комнаты A067: поток, примитивы A21A..A340, объекты A36A/A3AB/A405, зеркало AB29, интерфейс A548/AEFE/AABB/AA5D |
| screen.js | загрузчик таблиц AE00, цвета 8308, цвета ряда и темнота 8EB0, сокровищница A60B |
| room.js, vram.js, vdp.js, sound.js | указатели комнат, слой вывода игры (AEA7, AA96, 916C ...), OS7 (PUT/GET/FILL/регистры/спрайты), звук (SN->AY, эффекты AC1A/AC6D) |

Z80 остаётся только до старта уровня (8025..8413, A59D) и опрос джойстика (1F76 прослойки Muffie).

Сверка — `tools/modelcheck.js [итераций] [уровень] "план"`: два прогона модели MSX в coop (без подмен и с ними),
по итерациям A5D1 — ОЗУ 7000-733F, таблица имён, атрибуты спрайтов, цвета, PSG, переменные прослойки.
План: `т:клавиша+/-`, `т:tpРЯД.СТОЛБЕЦ` (телепорт; цвета ряда — `т:s70B1=10`), `т:sАДР=ЗН,..`,
`т:objK[+-d]` (герой на объект K списка 72C0), `т:tilXX[.n][v]` (герой на тайл XX: в 7058 / v — в 705B).
Переменные: `RND=зерно` (случайный ввод), `CHEAT=1` (жизни), `SET="т:адр=зн,.."`, `COV=от-до` (непокрытые
инструкции эталона), `COVB=1` (какой Z80-код игры исполнялся с подменами). Сценарии (все совпадают, уровни
1-3): обход 99 комнат, случайная игра, предметы в инвентаре, герой на объектах/верёвках/лестницах, выходы за
края, сокровищница. Покрытие: враги 278/288, предметы 383/391, двери 121/123, герой ~95% (нет: конец игры,
переход на следующий уровень из сокровищницы, захват верёвки в прыжке).

Найдено по пути: в coop кадр в сокровищнице не приходил — главный цикл ждёт сброса 705F бит 3 в A5D8 (A60B
из обработчика). Добавлена точка ожидания A5D8 (модель MSX, z2i HOOKS, nmi_wait_a5d8 в порте) — раньше порт
в сокровищнице зависал.

## Этап i8080 — порядок
Вывод сейчас — ~20000 команд на кадр вывода (клетки под спрайтами и анимация), логика — ~2800 на итерацию.
1. Спрайты с сохранением фона (как в kvalley-v06c): прямоугольник под спрайтом — в ячейку F900+ (невидимая
   плоскость), восстановление POP; клетки под спрайтами больше не перерисовываются.
2. Анимация банков: только клетки, где изображение тайла в новом банке другое (17 тайлов), из кэша POP.
3. Вывод без виртуальной VRAM: запись тайла логикой — сразу клетка на экран (+ копия таблицы имён для
   чтения логикой), смена цвета группы — её клетки, банк — живые клетки.
4. Логика вручную по модели (src/vec/manual/ через MANUAL транслятора, по процедуре), сверка
   tools/lockstep.js против MSX после каждой замены; горячие первыми: A7A1, 916C/9159, AEA7, 88D1, A9B3.
